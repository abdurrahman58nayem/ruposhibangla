# 🔁 GitHub কার্যপ্রবাহ (§২৬) — রূপসী বাংলা

## ব্রাঞ্চ কৌশল

| ব্রাঞ্চ | কাজ |
|---|---|
| `main` | সবসময় ডিপ্লয়যোগ্য; Vercel-এ প্রোডাকশন |
| `feat/<বিষয়>` | নতুন কাজ — PR-এর মাধ্যমে `main`-এ |
| `fix/<বিষয়>` | ত্রুটি সংশোধন |
| `data/<বিষয়>` | জ্ঞানভান্ডার/সিড হালনাগাদ (বড় CSV আমদানি) |

## প্রতিদিনের চক্র

```bash
git switch main && git pull
git switch -c feat/reels-autoplay
# … কাজ …
git add -A
git commit -m "রিলস: অটোপ্লে নিয়ন্ত্রণ যোগ"
git push -u origin feat/reels-autoplay
gh pr create --fill --base main
gh pr merge --squash      # পর্যালোচনার পর
```

## কমিট বার্তার নিয়ম

`<ক্ষেত্র>: <সংক্ষিপ্ত বাংলা/ইংরেজি বর্ণনা>`

ক্ষেত্র: `জ্ঞানভান্ডার`, `ফিড`, `রিলস`, `এআই`, `অ্যাডমিন`, `সেটিংস`, `ডেটা`, `নিরাপত্তা`, `ডক্স`, `নকশা`

উদাহরণ: `জ্ঞানভান্ডার: ২৫টি মাছের রেকর্ড যোগ`, `নিরাপত্তা: লগইন রুটে রেট লিমিটিং`

## CI (`.github/workflows/ci.yml`)

প্রতিটি PR ও `main`-এ পুশে চলে:

1. `npm ci`
2. `npx tsc --noEmit` — টাইপ যাচাই
3. `npm run lint`
4. `npm run build` — বিল্ড নিশ্চিতকরণ

Vercel নিজেই প্রিভিউ ডিপ্লয় তৈরি করে; `main`-এ মার্জ হলে প্রোডাকশন ডিপ্লয়।
